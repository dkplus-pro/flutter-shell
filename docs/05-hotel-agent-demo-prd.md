## 1. 背景与定位

在现有 Flutter 壳工程（`apps/shell_app`，P0–P8 已验收）内新增一个**酒店智能客服 Agent 演示**：住客在「服务」tab 与 AI 客服对话，可以**送拖鞋、送洗漱用品**（核心诉求），并扩展到毛巾/饮用水配送、信息问答与预约服务。

- **目标**：一套良好的 UI/UX 交互演示，体现 Agent 的三类能力——物品配送、信息问答、预约登记。
- **性质**：纯 Demo。**无真实后端、无真实 AI**，接口与数据全部 mock（脚本化意图引擎）。
- **平台**：仅 Android（壳工程现状：Android 完整实现，iOS 仅桩，本轮不变）。
- **成功标准**：按第 12 节「演示走查剧本」在模拟器上完整走通，全程无卡顿、无穿帮（无占位文案、无调试输出）。

## 2. 非目标（本轮明确不做）

- 真实 LLM API 接入（预留切换思路，但不实现，见 7.4）。
- 登录、账号、真实身份、支付、推送。
- 「我的订单」独立列表页（订单汇总用底部弹层承载，见 6.2.8）。
- 深色模式适配（锁定浅色演示主题）。
- 语音输入、图片消息、长按消息菜单。
- iOS 编译与运行验收。
- 多酒店/多房型数据切换。

## 6. 页面详述

### 6.1 聊天头部（AppBar）

- 左侧标题「AI 客服」（ARB key：`hotelChatTitle`）。
- 房号徽标：「1208 房 · 张先生」，由 mock 宾客档案渲染（D8）；仅展示，不可点击切换。
- 右侧订单图标（D11）：点击打开底部弹层「本次订单」，列出当前持久化存储中的全部订单（倒序），每条显示物品摘要 + 实时状态徽标 + 下单时间；弹层内状态与聊天卡片同步变化；空态文案「暂无订单」。弹层关闭即销毁，不新建路由页面。

### 6.2 消息流

**消息类型**（sealed model）：

1. **文本消息**：`role = guest | concierge`。左侧客服（灰白底、深色字、圆角气泡、带头像占位）；右侧用户（紫金色底、白字）。气泡最大宽度约 78% 屏宽。
2. **订单卡片**：见 6.3。
3. **时间分隔**：进入会话显示当天日期分组线；同一方两条消息间隔 > 5 分钟时插入 `HH:mm` 时间戳（D12）。
4. **输入指示器**：客服回复前显示「正在输入」三点动效气泡（占一条流内位置，不进持久化历史）。

**欢迎语**：首次进入（无历史记录时）客服自动发送开场白 + 一条引导（示例话术见 7.2 剧本 S0），并随消息流持久化。

**列表行为**：`ListView.builder` + 新消息自动滚动到底部；用户手动上滑查看历史时不强制吸底；键盘弹出时正确 `insets` 适配。

### 6.3 订单卡片与状态机（D6、D12）

**创建**：识别到配送/预约意图并完成槽位追问后，客服发送订单卡片：

- 配送类卡片：物品图标 + 名称、**数量步进器（−/数值/+，1–9）**、「配送至 1208 房」、主按钮「确认下单」。
- 预约类卡片（叫醒/延迟退房）：服务名 + 已收集的槽位摘要（如「明早 07:00 电话叫醒」）+「确认预约」。
- 点击确认 → 卡片原位切换为状态态；同一卡片**只允许确认一次**，确认后步进器与按钮不可再点（不可编辑历史消息）。

**状态机**（mock 定时器驱动，间隔为常量、可配置）：

```text
待确认 --确认--> 已下单 --约3s--> 配送中 --约8s--> 已送达 --用户点星--> 已评价
预约类：待确认 --确认--> 已预约（终态，展示预约时间）
```

- 状态态卡片展示：状态徽标（不同色）+ 物品摘要 + 进度提示文案（「已通知服务人员」「正在送往 1208 房」「已送达，祝您使用愉快」）。
- **已送达**后卡片尾部出现 5 星评价行（D12）：点击任意星级即提交 → 变为「已评价 · N 星」终态，只可评一次。

### 6.4 输入区与快捷面板（D7）

- 输入区常驻：`[+] [文本输入框] [发送]`；发送键在空输入时置灰。
- 点 `[+]` 在输入区上方展开**快捷面板**（2 行 × 4 列宫格，图标 + 文案）：

| 拖鞋 | 洗漱用品 | 毛巾 | 饮用水 |
| --- | --- | --- | --- |
| 叫醒服务 | 延迟退房 | WiFi 密码 | 早餐时间 |

- 点宫格项 = 以用户身份发送对应预设消息（如「我需要送几双一次性拖鞋到房间」），随后进入该意图的正常对话流；面板可收起，再次点 `[+]` 切换。
- 键盘与面板互斥：弹键盘收面板，开面板收键盘。

### 6.5 占位 tab（首页 / 我的）

- 简单占位页：居中图标 + 文案；点击页面任意处弹出「该功能暂未开发」（SnackBar，文案进 ARB）。

## 7. Mock Agent 设计（D2）

### 7.1 意图表

本地规则引擎：对用户输入做**包含关键词匹配**（大小写/全半角归一化），命中即进入意图流程；未命中走兜底话术并推荐快捷面板。优先级从上到下：

| 意图 | 触发词示例（zh，实际配置进数据层） | 类型 | 槽位 |
| --- | --- | --- | --- |
| `slippers` | 拖鞋 | 配送 | 数量 |
| `toiletries` | 洗漱 / 牙刷 / 牙膏 / 剃须刀 | 配送 | 数量 |
| `towels` | 毛巾 / 浴巾 | 配送 | 数量 |
| `water` | 水 / 矿泉水 / 饮用水 | 配送 | 数量 |
| `wifi` | WiFi / 密码 / 无线网 | 问答 | 无（直接回答） |
| `breakfast` | 早餐 / 早饭 / 几点 | 问答 | 无（直接回答） |
| `wakeup` | 叫醒 / 叫我起床 | 预约 | 时间（默认明早 07:00） |
| `lateCheckout` | 延迟退房 / 退房 | 预约 | 时间（默认 14:00） |
| `fallback` | 其余 | — | 推荐使用快捷面板 |

- 数量槽位：追问「请问需要几份/几双？」，用户回复纯数字或「X双/份」即收敛；回复「不用了/取消」退出流程。
- 时间槽位：解析「明天早上7点 / 07:00 / 下午两点」等常见表达；解析失败则给出两个快捷时间 chip 供点选。
- 全部 mock 文案（客服话术、卡片状态文案、面板文案、toast）**必须进 ARB（en + zh 双语）**，意图表数据层只存 ARB key / 枚举，不在代码里硬编码中英文文案（AGENTS §7 强制）。

### 7.2 演示剧本（验收走查用，话术以 ARB 为准）

- **S0 欢迎语**：客服「您好，我是 1208 房的智能管家小智，可以为您送物品、解答问题、设置叫醒～点右下角 + 可查看全部服务」。
- **S1 送拖鞋（主路径）**：用户「我需要两双拖鞋」→ 追问「好的，请问需要几双？」→ 用户「2 双」→ 订单卡片（数量 2）→ 确认 → 已下单 → 3s 配送中 → 8s 已送达 → 用户点 5 星 → 已评价。
- **S2 洗漱用品**：经快捷面板触发，数量步进器内直接改数量后确认（跳过追问的变体路径）。
- **S3 WiFi 问答**：用户「WiFi 密码多少」→ 直接回答（mock：`Hotel-Guest` / `12345678`，标注「演示数据」）。
- **S4 叫醒预约**：用户「明早 7 点叫我起床」→ 确认卡片「明早 07:00 电话叫醒，1208 房」→ 已预约终态。
- **S5 兜底**：用户输入无关内容（如「今天天气如何」）→ 客服礼貌兜底 + 引导快捷面板。

### 7.3 回复节奏（观感参数，做成常量）

- 「正在输入」指示 800–1500ms（随机）；打字机逐字输出，间隔约 30ms/字，标点后停顿 ×3。
- 订单状态流转：已下单 → 配送中 3s → 已送达 8s。
- 单条客服回复期间禁止并发第二条（队列化）。

### 7.4 预留切换（不在本轮实现）

意图引擎实现为 `ConciergeAgent` 接口的脚本实现（`ScriptedConciergeAgent`）；未来接真实 LLM 时新增实现并通过组合根注入替换，UI 与消息流不动。本轮不引入任何网络调用。

## 8. 数据模型与持久化（D10）

```text
ChatMessage   { id, role, type(text|order), text?, orderId?, createdAt }
HotelOrder    { id, kind(amenity|wakeup|lateCheckout), items[(nameKey, qty)],
              slotValue?, status, createdAt, updatedAt, rating? }
```

## 11. 风险与开放问题

| 风险/问题 | 处理 |
